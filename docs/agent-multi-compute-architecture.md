# 通用任务流程与多算力边界

> 本文保留早期版本的设计与实验历史。当前 1.2.12/1.0.16 的实现边界和验收结论以 [通用流程与验证](agent-generic-workflow-validation.md) 为准；下文“当前”指各段记录时的版本。

本记录更新于 2026-10-09。当前版本为 1.2.8，默认使用普通 ReAct，并对有工具执行的答案启用最多一次最终综合；结构化任务交付和多 Worker 模块需要显式启用。之前的工具契约报告描述 1.2.0；它不能证明后续修改或所有真机请求稳定。1.2.1 启用了任务交付协议，离线回归通过，但真机输出中的元数据排列被解析器拒绝，造成未执行工具、反复要求修正格式。此问题属于控制流程回归，不是算力设备没有完成推理。

## 当前设计

1. `TaskContract` 用 goals 声明每个交付项、必答字段、所需工具及事实/推导类别。数量、建议、额外写作均可作为字段，无衣服或特定问题分支。
2. `ReActAgentRunner` 执行注册工具，记录本次调用的证据和交付项关联。最终回答必须覆盖声明的交付项；进入最终校验后只允许一次修正，不重新执行工具。
3. `TaskPlanner` 生成依赖图；`TaskCoordinator` 调度就绪子任务，按可信工具策略决定能否并行。工作节点失败阻断其依赖节点，保留已完成的独立结果；不自动重放操作。
4. `ReActTaskWorker` 为子任务隔离模型、工具注册表、调用标识与取消范围。依赖结果沿任务图传递。
5. `ModelTaskAggregator` 在子任务结束后进行一次综合。结果必须引用本轮证据；综合失败仍保留工作节点结果。

工具通过注册的 schema、权限及证据字段扩展。计划和模型输出不能自行授予并行、写入权限，也不能将旧请求的结果当作本次结果。

## 已实现与尚未接入

以上模块有实际 Runner/Registry 集成测试，多个受控 Worker 可并行、等待依赖、隔离取消并最终综合。

当前手机界面仍直接使用一个 `RemoteComputeModel`，近场传输只有一个待完成推理请求；工具仍在 Agent 手机执行。尚未接入多设备 Worker 会话寻址、每设备容量协商、远端工具执行和远端工作节点结果协议。因此，不能将这些框架测试描述为多台物理算力设备已经共同执行任务或已经获得加速。

真实多设备接入应保留 taskId/subtaskId/attemptId/callId，按每设备实际容量分配会话。推理请求完成只代表模型返回；子任务完成还需要工具及最终答案校验。应用应区分这两个状态，避免把算力卡片“已完成”误认为整个 Agent 任务结束。

## 1.2.2 协议修复

- Plan、执行、最终修正三个阶段有各自的末尾提示，避免要求 Plan 又禁止 Plan。
- Execution 可以位于 For 前后，也可以在后续调用前重复相同模式。冲突模式、混合 Action/Final、未知工具和损坏参数仍使整批无效。
- 同工具的证据必须属于对应 goal，不能仅凭工具名认为全部交付项已执行。
- 用真机返回的两种元数据顺序建立回归，检查工具仅执行一次、最终修正不触发工具重跑。
- 纯 Final 已包含完整 JSON 时，仅移除文档之后冗余的根闭合符；不补写缺失内容、不截取第二份答案、不接受附加命令。需要模型纠正时提供被拒绝的原答案，避免只有抽象错误提示。

## 1.2.3 分阶段提示

1.2.2 的计算/换算真机测试通过，但复合任务仍出现规划类别缺失、事实与建议混在一个 goal、最终回复重新抄写 Action。三个工具均成功，Agent 因混合协议拒绝汇总。因此不能将 1.2.2 描述为复合任务已修复。

1.2.3 将初始规划独立为只输出 Plan 的请求，并明确事实与推导分项。取得声明工具的结果后，汇总提示使用完整证据账本，移除此前可执行的 Action 文本。若尚有真正依赖前一步结果的操作，仍可执行；模型开始 Final 后才禁止新增调用。一次最终修正只携带目标、证据、被拒绝答案和错误，不重放执行历史。引用前文的任务仍保留对话上下文。

## 验证与限制

### 1.2.8 最终展示与综合

1.2.7 真机生成了最终答案，但旧的自然语言措辞检查拒绝其时间窗表述，Agent 又显示了工具结果；模型还复述了草稿中的数量遗漏。独立测试精简中文、直接依据原始请求与证据的综合提示，模型给出了“两到三件”的推导建议。这个独立测试不等于 Agent 全链路通过。

当前最终综合不引用草稿，直接使用原始请求与完整当前证据；草稿仅在本地保留以应对综合传输失败。该组件没有工具调度接口，仍最多一次，取消优先。

工具可声明 `answerValidation: 'heuristic'` 区分自然语言启发式与严格校验。完成语义综合后，只有这类声明且实际成功的结果不再因措辞被拒绝。pending/failed 状态、默认严格校验、输出 schema、关联 ID、声明的数值/字面事实与权限均未放宽。编号属于展示，不参与数值事实匹配，也不能满足一个缺失的必答数值。

202 项行为检查、3 组严格类型检查通过，日志 `.hvigor/contracts-regression-1.2.8.log`。实际 ArkTS 编译、打包检查与独立签名通过，自动签名配置缺失情况同前。安装包 SHA256：`F875191CA92D6826DB368113E98B39194BFC10687848A4F1927747A87B457A92`。

### 1.2.7 通用分项回答

1.2.6 原问题真机结果已保留高铁类型、无时间窗内车次和真实地点/天气，但复核仍漏答建议数量。因此，1.2.6 的程序回归通过不能证明模型回答完整。

1.2.7 在同一个通用复核步骤中要求每个问题有独立编号部分，先给直接答案，再解释。明确的数量需求应给出数值、范围或无法确定的原因。该要求来自原始任务，不由衣服、城市或量词列表触发。领域检查兼容标题与正文分行，不将后一编号部分的事实串到前一部分。

199 项行为检查和 3 组类型检查通过，日志 `.hvigor/contracts-regression-1.2.7.log`；实际 ArkTS 编译、打包与独立签名完成，自动签名配置缺失情况同前。安装包 SHA256：`6BDDA61A86FCAE78FE781AC7C6147B56357A5D7DE571DB4790C3761DCD97F7F9`。

### 1.2.6 通用结束复核

公共 Core/Runner 中未保留“几件/几天”表达正则或穿衣专用检查。`FinalAnswerReviewer` 接收原始请求、完整草稿和本轮工具证据，统一复核漏项、约束和事实；手机与 LoopBackend 入口显式启用。普通聊天没有工具结果时不进行复核。

复核阶段没有工具调度权限，最多运行一次。返回新 Action、再次规划、损坏格式或传输失败时不继续循环；已通过工具契约事实检查的草稿可保留，并明确标注完整性未确认。草稿事实未通过检查时只保留真实工具结果。复核后的回答仍需通过工具自身事实校验，复核不能授予权限或覆盖证据。停止优先于任何草稿/最终发布。

工具领域的输入约束仍由对应契约负责，例如列车类型、路线、日期和时间窗，公共控制器不含列车或衣服名称。语言理解与结束复核仍由模型完成，模型检查不是完备的语义证明；替换模型需用同一套改写、不同领域、依赖、失败和取消测试验证。

198 项行为检查及 3 组严格类型检查通过，分别覆盖 21、19、6 个实际 ETS 文件（有重叠），SDK 仍有 2 条既有警告。新增测试包含任意工具改名、附加写作、复核新调用拒绝、复核失败保留、取消和证据不可绕过。日志 `.hvigor/contracts-regression-1.2.6.log`。

实际 ArkTS 编译、打包与独立签名通过，自动 SignHap 仍因配置指向缺失的个人证书失败；随后使用已有发布 profile 签名并覆盖安装为 1.2.6。日志 `.hvigor/build-agent-contract-1.2.6.log`、`.hvigor/sign-agent-contract-1.2.6.log`。SHA256：`6B50F036449A1D0B9316E0AB16A80BAAF4A748EC4C8165ABF5B7A50623210B25`。

### 1.2.5 阶段切换修复

已知必需调用未结束时只允许继续执行缺失项；已取得全部已知结果后才进入汇总。首轮提供必需工具名称，禁止将需求展示标签当作工具输入。该规则适用于任意契约声明或可选 Plan 声明的需求。

### 1.2.4 默认路径修复

1.2.3 真机仍未稳定生成规划 schema，默认强制规划不适合当前 Qwen2.5-7B。1.2.4 将 `taskContracts` 默认恢复为 false，`ReActTaskWorker` 仍显式使用结构化协议，等待后续模型适配验证。

默认路径依旧使用通用工具契约和真实结果校验；取得工具结果后，单独生成自然语言汇总，明确回答每个要求、数量及推导建议。提示保留完整当前证据和必要历史，不复制旧 Action。最终答案不再被“直接结果工具”的展示文字自动替换，避免用户同时要求的建议或额外写作消失。没有加入衣服、某个城市或某个计算式的专项流程。

离线入口：`node loop-chat/agent_core/tests/run-all.cjs`。1.2.2 的 190 项行为检查及 3 组严格类型检查通过；提供方和模型受控，不能代替真机。ArkTS 编译、打包检查通过；项目自动签名所指个人证书不存在，采用已有发布 profile 独立签名。
